title: "GitHub PR Sweep to Slack Workflow"
description: "Step-by-step checklist to schedule GitHub pull request sweeps and repository digests to Slack without an OS keyring"
---

OpenSRE allows teams to automate periodic digests — such as GitHub PR sweeps and repository work status reports — and deliver them directly to a Slack channel on a cron schedule.

This guide provides a copy-pasteable checklist to set up a GitHub PR sweep scheduled loop using environment variables without requiring OS keyring storage.

## Prerequisites

- An incoming Slack Webhook URL. See the [Slack Integration Guide](/messaging/slack#step-1-create-a-slack-incoming-webhook).
- GitHub integration configured and verified via `opensre integrations setup github`.

---

## Step-by-Step Checklist

### 1. Configure GitHub Integration

Before scheduling a PR sweep, ensure GitHub is authorized and registered on your host. Note that `opensre integrations setup github` opens an interactive prompt for browser authorization, so execute this step once during initial machine or workstation setup:

```bash
# Interactively register GitHub authorization and repo scope (run once during machine setup)
opensre integrations setup github

# Verify integration health and active status
opensre integrations verify github
```

<Note>
`opensre integrations setup github` is an interactive setup step that saves active credentials to `~/.opensre/integrations.json`. For non-interactive CI/CD runners or container deployments, either set `OPENSRE_INTEGRATIONS_STORE_PATH` to point to your pre-configured integrations JSON store path (or mount at `OPENSRE_CONTEXT_ROOT` / `~/.opensre/integrations.json`).
</Note>

---

### 2. Environment Setup for Slack (Without Keyring)

Export `SLACK_WEBHOOK_URL` directly in your environment or place it in your project's `.env` file:

```bash
# Slack channel incoming webhook URL
export SLACK_WEBHOOK_URL="https://hooks.slack.com/services/YOUR/WEBHOOK/URL"
```

<Note>
Using `SLACK_WEBHOOK_URL` in `.env` bypasses system keyring storage, making this approach suitable for headless servers, background daemons, and containerized deployments. See [Environment Variables](/configuration/environment-variables) for all supported options.
</Note>

---

### 3. Schedule the GitHub PR Sweep

Use `opensre cron add` to schedule a recurring PR sweep digest delivered to Slack:

```bash
# Schedule a daily GitHub PR sweep digest weekdays at 09:00 AM
opensre cron add --kind github_pr_sweep \
  --name "GitHub PR Sweep Digest" \
  --cron "0 9 * * 1-5" \
  --tz Europe/London \
  --provider slack
```

For more options on schedule expressions and timezones, see [Scheduled Deliveries (Cron)](/cron).

---

### 4. Verify Scheduled Tasks

List all configured cron tasks to obtain the newly generated task ID:

```bash
opensre cron list
```

---

### 5. Confirm Slack Delivery

Run the scheduled task immediately to confirm end-to-end delivery to your Slack channel without waiting for the next cron trigger:

```bash
opensre cron run <task_id>
```

---

## Copy-Pasteable Task Checklist

- [ ] Run `opensre integrations setup github` (interactive) and verify with `opensre integrations verify github`
- [ ] Set `SLACK_WEBHOOK_URL` in `.env` or process environment
- [ ] Set `OPENSRE_INTEGRATIONS_STORE_PATH` if using a custom integrations store path in container/CI environments
- [ ] Run `opensre cron add --kind github_pr_sweep --cron "0 9 * * 1-5" --provider slack`
- [ ] Run `opensre cron list` to retrieve the task ID
- [ ] Execute `opensre cron run <task_id>` and verify Slack message delivery
